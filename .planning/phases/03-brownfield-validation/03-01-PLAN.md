  <name>Task 1: Enhance Step 3 brownfield offer with existing-map handling</name>
  <files>get-shit-done/workflows/new-project-from-spec.md</files>
  <action>
  Modify Step 3 ("Brownfield Offer") in the workflow to handle three scenarios instead of two:

  **Current behavior (keep):**
  - `needs_codebase_map` is true → offer "Map codebase first" or "Skip mapping"
  - `needs_codebase_map` is false → continue silently

  **New behavior (add):**
  - When `has_codebase_map` is true (codebase map already exists in `.planning/codebase/`): add a NEW branch BEFORE the existing `needs_codebase_map` check:

  ```
  **If `has_codebase_map` is true** (from init — codebase map already exists):

  Use AskUserQuestion:
  - header: "Codebase Map"
  - question: "Found an existing codebase map in .planning/codebase/. Use it or refresh?"
  - options:
    - "Use existing" — Proceed using the current codebase map
    - "Refresh map" — Run /gsd:map-codebase to update, then return to /gsd:new-project-from-spec

  **If "Refresh map":**
  Run `/gsd:map-codebase` first, then return to `/gsd:new-project-from-spec`
  Exit command.

  **If "Use existing":** Continue to Step 3b (capability extraction).
  ```

  - Add a Step 3b after the AskUserQuestion:

  **Step 3b: Extract Codebase Capabilities**

  When `has_codebase_map` is true (user chose "Use existing" or map was already there):

  1. Read `.planning/codebase/ARCHITECTURE.md` and `.planning/codebase/STACK.md`
  2. Identify what the codebase already does — extract capabilities as a list
  3. Store as `codebase_capabilities` (a list of capability descriptions) for use in Step 7

  This mirrors the pattern from the interactive `new-project.md` workflow (lines 289-314) where codebase capabilities become Validated requirements.

  Also store `codebase_context_files` — the list of codebase map files that exist (ARCHITECTURE.md, STACK.md, and any others in `.planning/codebase/`) for passing to research agents in Step 10.

  **When user chose "Skip mapping" (existing `needs_codebase_map` path):** Set `codebase_capabilities` to empty list and `codebase_context_files` to empty list. Continue as greenfield.

  Keep the exit-and-return pattern (CONTEXT.md locked decision): if user needs fresh mapping, workflow exits and tells them to run `/gsd:map-codebase` then re-run.
  </action>

  3. Step 3b extracts capabilities from ARCHITECTURE.md and STACK.md
  4. `codebase_capabilities` and `codebase_context_files` variables established
