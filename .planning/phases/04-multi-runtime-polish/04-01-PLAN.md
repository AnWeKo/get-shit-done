<objective>
Add large spec folder resilience and edge case handling to the new-project-from-spec workflow.

Purpose: Spec folders over 100KB would overwhelm the context window during synthesis. This plan adds a priority-based content budgeting system that reads high-priority files (PRD, tech spec, constraints) in full and summarizes lower-priority ones when over budget. It also hardens edge case handling (non-markdown files, empty files, encoding issues).

Output: Updated workflow with content budgeting between Steps 4 and 5, plus edge case handling in Step 4.
</objective>

  Modify Step 4 ("Spec Folder Validation and File Reading") in the workflow to add content budgeting:

  **After sub-step 3 (reading each file's full content) and before sub-step 4 (display file list), add a new sub-step "Content Budget Check":**

  1. Calculate total content size across all read .md files (sum of character counts or byte lengths).
  2. If total <= 100KB: proceed normally — all files used in full. No changes to subsequent steps.
  3. If total > 100KB:
     a. Display a notice: `⚠ Large spec folder ({X} KB total) — applying content budget`
     b. After classification (Step 5) completes, apply priority ordering. The 9 existing classification roles map to priority tiers:
        - **Always full read (Tier 1):** PRD / Product Requirements, Technical Specification, Constraints / Non-functional Requirements
        - **Full read if budget allows (Tier 2):** Architecture / System Design, API Specification, Data Model / Schema
        - **Summarize when over budget (Tier 3):** User Stories / Use Cases, UI/UX Specification, Other / General
     c. Start with a 100KB budget. Deduct Tier 1 files (always included in full). Then add Tier 2 files in full until budget exhausted. Remaining Tier 2 and all Tier 3 files: the orchestrating agent produces a condensed summary of each (preserving key requirements, constraints, and any contradictory content — Claude's discretion on summarization approach).
     d. Replace the stored full content for summarized files with the summary text. Mark each summarized file with a `summarized: true` flag alongside its filename, role, and content.
     e. **Notification rule (from CONTEXT.md):** Only display which files were summarized when a summarized file later has conflicts or ambiguities detected in Step 6. Don't clutter output otherwise. Add a note in the synthesis step (Step 6) instructions: "If any file with `summarized: true` is involved in a contradiction or gap, include a note in the user prompt: '(Note: {filename} was summarized due to size; review original for full context)'"

  **Important:** This is a workflow instruction change — the workflow is a markdown prompt executed by an orchestrating agent, not code. Write the budget logic as clear procedural instructions the agent follows, not as code. Use the same style as the existing workflow steps.

  **Also update the edge case handling in Step 4:**
  - Non-markdown files: The existing sub-step 5 already warns about non-markdown files. Update the wording to match CONTEXT.md exactly: `⚠ Skipping {N} non-markdown files ({comma-separated list up to 5 names}...)`
  - Empty .md files: After reading each file (sub-step 3), skip files that are 0 bytes or contain only whitespace. Do NOT count them in the file total or display them in the file list table. Add instruction: "Skip .md files with no content (0 bytes or whitespace only) — do not count, list, or classify them."
  - File encoding: Add instruction: "If a file cannot be read cleanly (encoding errors, binary content), read what's readable and continue. Do not abort the workflow for a single unreadable file."
