**8b. Analyze spec prose for config signals:**

The agent scans all classified spec file content (from Step 5) for config preference signals. Config keys to attempt inference on:

| Config Key | Spec Signals → Value |
|------------|---------------------|
| `mode` | "move fast", "no blockers", "fully automated" → yolo. "careful", "review each step" → interactive |
| `depth` | "rapid prototyping", "MVP", "ship fast" → quick. "production", "enterprise" → comprehensive. Default: standard |
| `parallelization` | "speed matters", "fast execution" → true. Default: true |
| `commit_docs` | "track everything", "audit trail" → true. Default: true |
| `model_profile` | "high quality", "thorough analysis" → quality. "budget", "cost efficient" → budget. Default: balanced |
| `workflow.research` | Always true for spec-from-file flow (locked decision: research always runs) |
| `workflow.plan_check` | "verify", "quality gates" → true. Default: true |
| `workflow.verifier` | "verify", "validate work" → true. Default: true |

**Skip inference for purely technical keys** that don't have natural prose mappings (e.g., max_parallel_agents) — use defaults.

**Conservative inference:** Only set a value when the signal is very clear. When remotely ambiguous, mark as "needs confirmation."

**8c. Present unified config view with citations:**

Display ALL config values in one view:
- Inferred values: show the spec passage that drove the inference (e.g., "`tech-spec.md` line 12: 'rapid prototyping' → depth: quick")
- Default values: show "(default)" with brief rationale
- Contradictory signals: show both citations, ask user to choose (same pattern as Phase 1 contradiction handling)

**Per-value choices** — each configurable value gets its own AskUserQuestion option set, NOT a single freeform prompt. Present as a batch using AskUserQuestion with multiSelect or a series of questions.

**8d. Show summary and proceed:**

After config is finalized, display a summary of all final values and their sources. Log any user overrides as decisions in PROJECT.md's Key Decisions table (using the pattern: `| Config: [key] set to [value] | User override — spec suggested [other] | — Active |`).
