**If refactoring `cmdRoadmapAnalyze` is too invasive**, create `cmdRoadmapUnplanned` as a standalone function that reads ROADMAP.md, reuses the same phase-header regex pattern, and checks disk status — duplicating ~20 lines of the analyze logic but keeping the existing function untouched. **Filter criteria (from CONTEXT.md — locked decisions):**
A phase "needs planning" if BOTH conditions are met:
1. Has NO `*-PLAN.md` files on disk (plan_count === 0)
2. Is NOT marked complete in ROADMAP.md (`roadmap_complete === false`)

**Output JSON:**
```json
{
  "unplanned": [
    {
      "number": "5",
      "name": "Command & Phase Discovery",
      "goal": "User can invoke /gsd-plan-all ...",
      "disk_status": "discussed",  // empty|discussed|researched|no_directory
      "has_context": true,
      "has_research": false
    }
  ],
  "count": 1,
  "total_phases": 7
}
```

**Disk status values for unplanned phases:** `empty` (directory exists, nothing in it), `discussed` (has CONTEXT.md), `researched` (has RESEARCH.md), `no_directory` (phase dir doesn't exist yet).

Phases with `planned`, `partial`, or `complete` disk_status are EXCLUDED (they have plans).

Sort unplanned phases by ascending phase number.
